# Segurança

## Relato privado

Envie suspeitas de vulnerabilidade para **joaoaquino.dev@outlook.com**, com o assunto “Pellum — relato de segurança”.

Descreva a área afetada, os passos mínimos e o impacto observado. Use dados fictícios e informe a versão ou commit quando possível. Não envie senhas, tokens, prontuários, fotos ou exportações de pacientes.

Não publique detalhes exploráveis em issues ou pull requests. Não acesse registros de terceiros, execute exclusões ou teste carga no ambiente de produção. Testes precisam ter escopo e ambiente autorizados.

## Referência técnica

A main contém a aplicação independente; a infraestrutura histórica restante está identificada em docs/LEGACY.md. Confira o [mapa das versões](docs/REPOSITORY_GUIDE.md) para identificar a base afetada. Não presumir que um commit disponível no GitHub está publicado.

A documentação de auditoria registra controles e limitações em um momento específico; não garante ausência de vulnerabilidades. Histórico interno de snapshots não substitui backup externo validado.

## Tratamento

O responsável avalia o relato, reproduz em ambiente controlado e define a correção e a publicação. Não há prazo de resposta garantido ou programa de recompensas estabelecido por este documento.
